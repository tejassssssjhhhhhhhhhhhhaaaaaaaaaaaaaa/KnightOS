# KnightOS – System Architecture & Core Experience

## 1. Single Source of Truth (SSoT)

Every real-world fact (e.g., Home Location, Salary, Sleep Goal) exists exactly once in the `MemoryTable`.
- Modules (Health, Finance, Planner) must query the `MemoryEngine` for canonical facts.
- Data imported from different sources is merged into one logical fact chain using SHA-256 deduplication and semantic mapping.
- **Reactive Propagation**: All modules use `watch` APIs to automatically reflect changes in the canonical memory without manual polling or refresh logic.

## 2. Knowledge Confidence Lifecycle

Every memory in KnightOS exists in one of the following states:

| State | Definition | trust_weight |
| :--- | :--- | :--- |
| **Observed** | Directly imported from trusted sources (Timeline, medical records). | 0.9 |
| **Inferred** | Generated by Knight through reasoning (e.g., "Home Candidate"). Requires confirmation. | 0.4 - 0.9 |
| **User Confirmed** | Explicitly verified by the owner. | 1.0 |
| **User Corrected** | Rejected or modified by the owner. | 1.0 (Correction) |
| **Deprecated** | Historically true but no longer current. | 0.0 (Reasoning) |

### Memory Promotion Rules
- `Observed` -> `User Confirmed`: When a user validates imported data.
- `Inferred` -> `User Confirmed`: When Knight's guess is validated.
- `Inferred` -> `User Corrected`: When a user edits a guess.
- Any State -> `Deprecated`: When new information supercedes the old version.

## 3. Explainable Intelligence (The Reasoning Chain)

Knight never produces unexplained conclusions. Every inference must expose:
- **Confidence Score**: Calculated probability of accuracy (0.0 to 1.0).
- **Evidence**: Raw data points used (e.g., "67 overnight stays").
- **Explanation**: Human-readable reasoning string explaining "Why" Knight believes this.
- **Provenance**: Permanent record of the data's origin (e.g., "Samsung Health Import").

## 4. Verification Loop

Knight proactively promotes "Inferred" knowledge to "Confirmed" status through the Socratic verification mission.
- **Verification Engine**: Scans for high-importance, unverified inferences. Implements periodic revalidation for critical identity and health data.
- **Discovery Engine**: Prioritizes verification missions over general exploration to ensure core facts are solid.
- **Knight Orb**: Deliver interactive `VerificationBubble` widgets for tap-to-confirm feedback.

## 5. Reactive Memory Infrastructure (ADR-002)

Implemented using Drift `watch` APIs to provide a fully reactive data layer.
- **watchLatest(memoryId)**: Stream of the current state of a fact.
- **watchByCategory(category)**: Stream of all latest facts in a knowledge book.
- **Performance**: Streams are optimized to only notify when the `isLatest` version of a logical memory ID changes.

## 6. Intelligence Platform (The Brain)

A unified reasoning core that coordinates domain-specific intelligence modules.
- **Intelligence Bus**: Event-driven hub for `DataChangedEvent` and `ContextChangedEvent`.
- **Orchestrator**: Plugin-based brain that manages layered reasoning (Observation → Synthesis → Prediction).
- **Explainability**: Every conclusion includes a `ReasoningTrace` with evidence, confidence, and source metadata.
- **Intelligence Timeline**: A complement to the Life Atlas, recording Knight's evolving understanding (e.g., "Routine Discovered").

## 5. Visual Standards (Horizon Language)

- **Colors**: strictly adhere to `DesignColors` for semantic consistency.
- **Atmosphere**: Use `DesignGradients.horizon` and atmospheric glows.
- **Stars**: Individual data points in the Discovery "Night Sky."
- **Constellations**: Completed knowledge domains (The 11 Books).
